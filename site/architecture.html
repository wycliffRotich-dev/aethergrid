Architecture, built to be read

AetherGrid is organised in four layers with dependencies pointing inward. The domain holds the rules, the outer layers hold the details, and every non-obvious decision is written down in a public decision record.

Presentation

FastAPI endpoints for jobs, nodes, workers, events, cluster health and API keys. They validate input, call an application service and return the response. No business logic lives here.

Application

Services that coordinate domain objects and repositories. The worker execution loop runs each job as a real subprocess and keeps its lease renewed. The reconciliation loop recovers crashed workers, expired leases and inconsistent state.

Domain

Job, Node, Worker, Lease, Event and ApiKey enforce their own invariants. Scheduling policy and the job lifecycle live here as plain Python, with no FastAPI or psycopg imports.

Infrastructure

PostgreSQL repositories written with raw psycopg, so query behaviour and transaction boundaries stay visible. Every repository is validated by a shared contract test suite.

How recovery stays safe

A domain that stands on its own

Business rules sit in plain Python and do not depend on the web framework or the database. The layer boundaries are enforced by a test, so the structure stays as designed as the system grows.

Domain owns scheduling (ADR 0018)Layers enforced by a test (ADR 0082)Job lifecycle (ADR 0016)Architecture index test (ADR 0084)

Ownership through leases

A job is owned through a renewable lease. The worker renews it continuously for the whole run, and if a renewal fails the worker discards its result instead of writing it against another owner's work.

Lease ownership (ADR 0005)Continuous renewal (ADR 0014)Worker execution loop (ADR 0006)Cancel via renewal (ADR 0029)

Reconciliation as a core mechanism

A reconciliation loop finds crashed workers, expired leases and jobs abandoned mid-cancellation, and repairs them. It re-checks lease validity at the moment it acts.

Reconciliation loop (ADR 0007)Reclaim and repair (ADR 0011)Abandoned mid-cancellation (ADR 0031)Fenced by expiry (ADR 0052)

One scheduler, elected safely

A single scheduler is elected with a database advisory lock, and the cluster tick runs off the event loop so the API stays responsive while the cluster is being managed.

Advisory lock election (ADR 0078)Tick off the event loop (ADR 0032)Liveness and readiness (ADR 0050)Best-fit scheduling (ADR 0043)

Persistence you can reason about

Raw psycopg keeps every query and transaction boundary explicit. PostgreSQL and the local backends are held to the same behaviour by shared contract tests, and the schema moves forward through versioned migrations.

psycopg over an ORM (ADR 0001)Repository parity (ADR 0010)Versioned migrations (ADR 0071)Startup schema check (ADR 0072)

Workers that clean up after themselves

A job's command is stopped along with anything it left running, whether the job finishes, times out, is cancelled or loses its owner. A command that cannot start fails with a clear outcome.
